# 3. Browser SDK, Cryptographic Decision Tokens & Proof-of-Work

This guide explains how to embed the **BotPulse Edge Sensor** (`backend/sdk/botpulse.js`) into any web application, how signed decision tokens work, and how the silent SHA-256 Proof-of-Work (PoW) defense operates.

---

## Part 1: Browser Tracking SDK (`botpulse.js`)

The SDK is a single, zero-dependency UMD/IIFE JavaScript file (**v1.4.0**) served directly by the backend at:
- `GET /botpulse.js`
- `GET /api/v1/botpulse.js`

### Quick Integration Snippet

Add this script to the `<head>` or before `</body>` of any protected website:

```html
<script src="https://your-botpulse-backend.example.com/botpulse.js"></script>
<script>
  window.BotPulse.init({
    siteKey: "bp_pub_alvera_live_7c4f19e",
    endpoint: "https://your-botpulse-backend.example.com/api/v1",
    batchIntervalMs: 2500,
    batchSize: 25,
    onDecision: function (decision) {
      // decision = { action, riskScore, token, powChallengeIssued, pow_verified }
      console.log("BotPulse verdict:", decision.action, "Risk:", decision.riskScore);
    }
  });
</script>
```

### Configuration Options

| Option | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `siteKey` | `string` | *(required)* | Public site key generated in the SOC Dashboard (`/api/v1/websites`). |
| `endpoint` | `string` | `http://localhost:8000/api/v1` | Base API URL. Can also be overridden dynamically via `?bp_api=...` or `?api=...` URL query parameters (saved to `localStorage`). |
| `enabled` | `boolean` | `true` | Toggle telemetry capture on/off. |
| `batchIntervalMs` | `number` | `2500` | Periodic flush interval in milliseconds. |
| `batchSize` | `number` | `25` | Auto-flush threshold when the queue reaches this many events. |
| `apiKey` / `geminiApiKey` | `string` | `null` | Optional AI agent credential for RAD-S1 Layer 3 attribution. |
| `onDecision` | `function` | `null` | Callback invoked whenever a new or PoW-upgraded decision token arrives. |

### What Telemetry Does `botpulse.js` Capture?

All listeners are attached with `{ passive: true }` so they never degrade scrolling or UI responsiveness:

- **Session & Visitor Identity:** Persists `bp_session_id` in `sessionStorage` and `bp_visitor_id` in `localStorage`.
- **Cursor & Touch Kinematics (`mouse_move`):** Throttled to every **45 ms**; records `{ x, y, screen_w, screen_h, touch? }`.
- **Click Events (`click`):** Records `{ x, y, tag, class_hint, button }`.
- **Scroll Depth (`scroll`):** Debounced at **100 ms**; records `{ scroll_y, depth_percent }`.
- **SPA Route Transitions (`page_view`):** Hooks `history.pushState` and `popstate` automatically; records `{ title, referrer, path }`.
- **Custom E-Commerce Events:** Call `BotPulse.trackEcommerce('add_to_cart', { sku: 'ELV-01' })` to emit `ecommerce_add_to_cart`.
- **Unload Delivery:** Listens to `visibilitychange` (`hidden`) and flushes remaining queued events using `navigator.sendBeacon`.
- **Resilience:** If a network POST fails, events are re-queued (capped at the latest 50 events to prevent memory bloat).
- **Resemble.AI Verdict Bridge:** Automatically listens to the `resemble:verdict` `CustomEvent` and polls `window.ResembleAgentDetection.onVerdict(...)`, forwarding live verdicts (and optional signed tokens) immediately to the backend.

### Public SDK Methods

- `BotPulse.init(config)` — Initialize tracking and listeners.
- `BotPulse.getDecisionToken()` — Returns the latest signed `HS256` Decision Token (from memory or `sessionStorage`).
- `BotPulse.trackPageView()` / `BotPulse.trackEcommerce(action, details)` — Emit manual events.
- `BotPulse.setResembleVerdict(detail)` / `BotPulse.setResembleToken(token)` — Bridge Resemble.AI signals.
- `BotPulse.setApiKey(key)` / `BotPulse.setGeminiApiKey(key)` — Attach agent attribution credentials.
- `BotPulse.flush(useBeacon)` — Force immediate delivery of queued events.

## Part 2: Cryptographically Signed Decision Tokens

Every telemetry batch returns a signed **Decision Token** generated by `issue_decision_token()` in `backend/core/crypto.py`. Protected backends (such as ÉLVARA Fashion's checkout/cart server) attach and verify this token on sensitive endpoints without needing a round-trip to BotPulse on every request.

### Token Format

Standard unpadded Base64URL **JWT (`HS256` / HMAC-SHA256)** signed with `BOTPULSE_SECRET_KEY`:

```text
<headerB64>.<payloadB64>.<hmacSha256SignatureB64>
```

**Decoded Payload Claims:**

```json
{
  "sub": "sess_a81f39c0_1731932000000",
  "site_id": "site_alvera_001",
  "action": "ALLOW",
  "risk_score": 0.08,
  "risk_level": "LOW",
  "visitor_type": "HUMAN",
  "decision_id": "dec_9f3c2a1b4e8d_1731932005",
  "iat": 1731932005,
  "exp": 1731935605,
  "permitted_scope": ["checkout", "cart", "search", "auth"],
  "pow_verified": false
}
```

- **Validity Window:** `DECISION_TOKEN_EXPIRE_SECONDS` = **3,600 seconds (1 hour)**.
- **Enforcement Feedback Loop:** After the protected application verifies the token and applies the decision (`ALLOW`, `VERIFY`, `RATE_LIMIT`, or `BLOCK`), it posts a confirmation to `POST /api/v1/enforce/feedback` so the SOC Dashboard tracks *Decision Issued → Enforcement Applied*.

## Part 3: Silent SHA-256 Proof-of-Work (PoW) Challenge

When a session receives a **`VERIFY`** verdict (moderate risk, undetermined Resemble review, or unverified AI agent), BotPulse avoids intrusive visual CAPTCHAs by issuing a **silent client-side Proof-of-Work challenge**.

### How the Protocol Works

1. **Challenge Issuance (`generate_pow_challenge` in `crypto.py`):**
   - Server generates a unique `challenge_id`, random hex `seed`, expiration timestamp (`expires_at`, default 90 s TTL), and site-configured `difficulty` (bounded strictly between `2` and `5`, default `3`).
   - Server signs the parameters with HMAC-SHA256 bound to `session_id` and `site_id`:
     $$\text{sig} = \text{HMAC-SHA256}(\text{SECRET\_KEY},\ \text{challenge\_id:seed:difficulty:expires\_at:session\_id:site\_id})$$
   - This prevents attackers from tampering with difficulty, extending expiry, or transferring challenges across sessions.

2. **Browser Solving (`solveProofOfWork` in `botpulse.js`):**
   - The SDK searches for an integer `nonce` ($0 \le \text{nonce} < 2{,}000{,}000$) such that:
     $$\text{SHA-256}(\text{seed} + \text{":"} + \text{nonce}) \text{ starts with } \underbrace{\text{"00...0"}}_{\text{difficulty zeros}}$$
   - Uses native Web Crypto (`window.crypto.subtle.digest('SHA-256', ...)`) in HTTPS contexts, with a built-in pure-JS RFC 6234 SHA-256 fallback for plain HTTP development.
   - Yields to the event loop every 250 iterations if a slice exceeds 12 ms so the page stays at ~60 fps.

3. **Server Verification & Token Upgrade (`verify_pow_submission` in `prevention_service.py`):**
   - Submits the solution to `POST /api/v1/prevention/pow/verify`.
   - Server verifies:
     1. Parameter types and difficulty bounds (`2 <= difficulty <= 5`).
     2. Challenge has not expired.
     3. Session binding matches (constant-time `hmac.compare_digest`).
     4. Challenge HMAC signature is intact.
     5. Computed `SHA-256(seed:nonce)` satisfies the leading-zero prefix.
     6. **Replay Protection:** Rejects any `challenge_id` already redeemed in memory or in the `pow_challenges` database table.
     7. **No Block Bypass:** If the session's server-side enforcement state is `block`, verification is rejected (`SESSION_BLOCKED`).
   - On success, the server computes a moderated risk score (`max(15.0, existing_risk * 0.6)`), records a **300-second PoW grace window** (`POW_SESSION_GRACE_SECONDS`), logs the solve time to `pow_challenges`, and returns an upgraded `ALLOW` Decision Token with `"pow_verified": true`.

### Difficulty Reference

| Difficulty | Leading Hex Zeros | Expected Avg Hashes | Typical Browser Solve Time | Use Case |
| :---: | :---: | :---: | :---: | :--- |
| `2` | `00...` | ~256 | < 10 ms | Fast / low-friction screening |
| `3` *(Default)* | `000...` | ~4,096 | ~30 – 120 ms | Standard silent verification |
| `4` | `0000...` | ~65,536 | ~0.5 – 2 s | Heavy bot pressure |
| `5` | `00000...` | ~1,048,576 | ~8 – 25 s | Severe attack / rate-abuse defense |
